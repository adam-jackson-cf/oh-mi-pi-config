# Proofs

Load the API with `%load <extension>/lib/rails_kernel.py`; `help(freeze)`, `help(prove)` and
`help(structure_review)` give the arguments.

- A proof is an outcome test or a deterministic lever journey for one user-facing behaviour, linked
  from its feature-map entry; never a live paid or LLM call or T3 exploration.
- Assert the broken or newly requested outcome, never an infrastructure failure, and never weaken a
  proof to make it red.
- Proof commands defeat result caches (`go test -count=1`).
- A regression found later sets `parent` to the defective commit.
- A behaviour the plan did not name gets a map entry and an outcome test, then a re-freeze with
  `previous=` and every earlier proof, before the PR opens.
- A lost manifest is the `manifest` field of its head's `prove()` result.

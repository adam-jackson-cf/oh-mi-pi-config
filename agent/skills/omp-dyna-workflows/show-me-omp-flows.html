How OMP carries a request from prompt to merged PR

One non-trivial engineering request, left to right through six proof-first stages. Rows are the components that act at each stage. Red cards are hard blocks the skill-gate extension enforces. Violet cards are Jev-judged warnings. Green cards are deterministic checks. Everything else is instruction the agents follow. Source of truth: SKILL.md, agent/config.yml, agent/skill-gates.yml, agent/extensions/skill-gate.ts, templates/workflows.py, skill://git-tool.

Principles behind the proof-first flow

Distilled from poteto's pstack (findings only count when a run proves them), OpenAI Pando (a branch per agent, risk-tiered review) and trunk-based development. Each card names where the principle is enforced: hard blockskill-gate refuses the action deterministica script decides instructionagents are told, nothing stops them.
01

Proof over opinion

An abstract agent review is an opinion; a finding that carries the command and its output is evidence.
deterministicverify() runs the proofs; instructionverifier brief and blocking rule drop anything not run.
02

A plan is a draft until a spike answers its open questions

Least effort that answers a pass/fail predicate, written before anything runs, on the real surface.
instructionomp-dyna-workflows playbooks; kiss cuts questions first.
03

Proofs before code

A frozen manifest means the proof cannot be bent to fit the implementation afterwards.
deterministicverify() manifest and proof-file hashes; instructionproof task is spawned before the implementation task.
04

Red for the right reason, green twice

A defect proof that passes on the parent proves nothing, and one that passes once may be flaky. preserve proofs must pass at the parent; new-surface red at the parent is true by definition.
deterministicverify() parent overlay (expectRed substring) and two head runs.
05

Independent, cross-family verification

A model family shares blind spots with its own output; the verifier must not be the author's family.
hard blockskill-gate before_subagent_spawn refuses a verifier whose family matches any author.
06

Deterministic first, Jev second, judgement last

Cheap, repeatable checks settle what they can; Jev warns on patterns; a model judges only the remainder.
deterministicverify() runs before the verifier; instructionJev TTSR rules warn.
07

Structure and naming are checks, not advice

A rule nobody runs decays; implementation needs a repo that can say no.
deterministicrepo pathCheck and fastGate; instructionmissing either routes through setup-repository-guardrails first.
08

The test suite is governed

Tiers, budgets, growth limits and placement keep the suite fast enough to run on every change.
deterministicrepo pathCheck, commitGate, gate; hard blockwithout a pathCheck, skill-gate requires the tiers ref for a test path.
09

Trunk-based units

Short-lived agent/* branches, same-day merge, green on every commit; multi-phase work lands behind a flag with a removal criterion.
deterministiccommitGate keeps commits green; instructionskill://git-tool branch model.
10

Risk-tiered merge authority

Docs-only merges on green; verified work merges after one cross-family run; the owner merges sensitive paths.
hard blockskill-gate on gh pr merge vs sensitive; deterministicverify() reports needs_owner.
11

Delegate code; the main agent never patches

Keeps the author family known, the main context small, and fixes inside the proof loop.
instructionomp-dyna-workflows and task briefs; the stop gate requires fastGate to have run after any tree change.
12

Least effort, delete dead weight

The cheapest correct change wins; cutting scope before a spike is cheaper than spiking it.
instructionkiss cuts criteria and open questions at Frame; clean-cutover rule.

Six stages · who acts

1 · Frame

Main selects one playbook, captures all requested outcomes and reads readiness/query-selection before discovery. Kiss removes unnecessary work/questions, never requested behaviour. Read-only scout maps genuinely unknown ownership.

2 · Spike

Main fetches the resolved remote default and creates a detached tree. Task performs the bounded experiment; main saves the report before tree removal. Reproduction and setup inventory are mandatory; other spikes answer remaining questions. Spike code never lands.

3 · Plan

Main maps criteria to named proofs. Draft until spike answers land; missing proof surfaces are first tasks. Each multi-phase unit, including final flag removal, has its own manifest and PR.

4 · Implement

Prerequisite: valid controls and installed hook. Missing controls route to an owner-approved project-setup prerequisite PR; install its approved hook before the first commit.

Proof task leaves files uncommitted → main freezes → separate implementation task (configured task model) commits proofs with the greening change, pushes, authors the body, opens the PR and waits for exact-head CI. Main never commits.

Freeze checks the pinned baseline by proof kind; defect red must contain the asserted reason, absent from the truncated-file negative control. Infrastructure is not red. Documentation-only proofs are preserve: freeze overlays the new text, so they check head wording only.

Designer owns presentational work and scores 10 principles, each 0–2, inspecting screenshots—not a ten-point total.

5 · Verify

Main independently confirms writer-ready green CI, then calls prove in Python eval (or fresh docs exemption). Prove dispatches the sole cross-family verifier; no second review task.

Use the configured verifier model only when its family differs from every recorded author. Otherwise select an eligible cross-family model through verifier_model: always a verifier, never a task substitute. Rails decides family eligibility.

Dependabot PRs without an author ledger count as external only when GitHub confirms the Dependabot PR author, a dependabot/ head at the checked-out SHA, and verified dependabot[bot] commits across a nonempty range. Main freezes a preserve full-gate proof and runs prove; never re-apply the bump as an agent PR.

Main posts evidence, then labels only after verification and exact-head green CI.

6 · Integrate

Main rechecks exact-head eligibility and merges under merge-and-recover, respecting agentMerge: disabled. --auto is useful only with actual required checks and does not finish the job: wait for MERGED.

NUC sync uses the documented merge-commit exception. Serial integration and post-merge recovery have one home: git-tool.

Outcome-first verification

Under DynaFlows, global test-guidance rules override repo-local test rules; .omp/test-profile.md supplies values and may tighten them. Plan reads tiers, case selection and suite budgets.

User-visible work without a verification surface first completes owner-approved Project setup, including guarded repos in surface-only extend mode. An approved no-runnable-app exemption does not divert config or skill work. Setup demonstrates a broken variant in scratch, then discards that code. Proof tasks write the lever and runner-invoked journeys, freeze them together as preserve proofs; new-control canaries remain new-surface. Implementation writes map, profile and guardrails, in that order; Step 5 approval remains mandatory and the hook precedes the first commit.

Outcome tests drive public entry points; property tests cover pure cores. Lever journeys use defect with asserted expectRed or preserve, never new-surface. Run them repeatedly before freeze; doctor/environment failures are not accepted red. Proof briefs read case selection, naming/layout, outcome tests, tiers and profile, plus property, determinism, statistics and surface guidance when applicable. Implementation reads surface guidance for mapped-feature changes and edits map docs only, not frozen lever bytes. Verifiers use the profile lever with temporary data and evidence.

T1 has no processes or network; T2 owns seams and boundary-crossing journeys; T3 owns agent exploration and live paid calls. Commit runs static checks, T1 and affected T2; CI runs T1 + T2; nightly adds T3 on scheduler-enumerated active branches. Approved per-machine timing limits block locally only; CI timing is report-only, but missing, invalid or stale reports fail everywhere. First limits and raises need approval.

Ready PR → evidence → merge

1 · Writer readyNo pending edits; exact pushed SHA has required green CI. Main independently confirms existing/cached exact-SHA status.
2 · Main prove / exemptProve validates full-PR range and hashes, runs each head proof twice and earlier proof-bearing commits once with their own bytes; baseline overlays remain isolated. The sole verifier drives live criteria. Eligible docs use a fresh exemption without manifest/verifier.
3 · Evidence + label → mergeMain posts the result outside the PR body. Rails enforce exact-head green checks before the label always and at merge only with dynaflows on, plus a valid pass marker with dynaflows on. NUC policy requires a successful gate commit status, not a check run. Main applies agent-verified only after both pass, then follows git-tool integration.

Every new SHA repeats its full risk tier and CI, including a fresh eligible docs exemption. Three post-first-prove writer fix cycles maximum are recorded in PR comments; pure rebases invalidate evidence but do not consume a fix cycle. See verify-loop for changed-head, pending/timeout/error and escalation mechanics.

Ordinary reporting: writer lists discovered gate paths/effects under Gate changes; a changed path alone is not a blocker. Escalation: exhausted fix cycles, unavailable independent models and unresolved CI incidents require the actual blocker, not a bypass.

The exact verifier blocker is BLOCKING_RULE, not a copied list here. Source status/HEAD changes mean “source checkout changed during verification”; this does not attribute causation or promise a sandbox.

CI host and Jev are not alternate merge authority

ciHost defaults to github. NUC serves explicitly allowlisted adam-versed and adam-jackson-cf repositories, each using its owner's token; it is never a default. The checkout's gate is authoritative: NUC requires an exact-head successful gate commit status even with an empty rollup or no checks.ci; a check run named gate does not count. The label CI gate always applies; the merge gate applies only with dynaflows on. Writer submits/waits for exact-head CI. The NUC runs rootless Podman/gVisor with publishing credentials on the host, posts exact-SHA status, and retains evidence. Generic Actions fallback is not autonomous permission unless the documented fallback posts every required status; otherwise escalate the incident under git-tool.

Jev TTSR warnings can trigger at any stage on a main-agent reply: regression coverage, clean cutovers, flakes and measured claims. Their placement is not a stage gate. Subagents get explicit references in briefs and their own rails checks. Deterministic checks precede Jev single-state judgement; contextual critique belongs to an independent reviewer.

Principles · different kinds of enforcement

The design rubric has ten principles scored 0–2 each; the workflow principles below explain the system, not a second design rubric.

  1. Proof over opinion.

    Check: deterministic proof execution.

    Instruction: verifier findings carry live commands and output.

  2. Questions before experiments. Frame only plan-changing uncertainty; save scratch evidence before removal.
  3. Proofs before implementation.

    Check: frozen hashes and own-byte earlier-commit execution.

    Instruction: ordered proof/main-freeze/implementation actors.

  4. Independent verification.

    Hard block: rails author-family eligibility at every prove dispatch and, with dynaflows on, at standalone verifier spawn.

    Instruction: separate read-only sessions and evidence, not inherited author context.

  5. Deterministic first. Infrastructure failure is not red evidence; judgement cannot turn it into pass.
  6. Governed structure and tests.

    Check: repository path/commit/CI controls.

    Hard block: missing required references or unresolved path failures.

  7. Short-lived units. Independent units land serially; final flag removal is a verified unit, not an afterthought.
  8. Risk-tiered authority. Fresh eligible docs exemption or prove, exact-head green CI and main evidence/label; disabled agentMerge still needs owner approval.
  9. Delegate implementation. Main coordinates and verifies; the writer commits through the hook and delivers the ready PR.
  10. Least correct work. Cut needless work, never requested behaviour; remove obsolete paths in the canonical cutover.

How OMP carries a request from prompt to merged PR

One non-trivial engineering request, left to right through six proof-first stages. Rows are the components that act at each stage. Red cards are hard blocks the agent-rails extension enforces. Violet cards are Jev-judged warnings. Green cards are deterministic checks. Everything else is instruction the agents follow. Source of truth: SKILL.md, agent/config.yml, agent/agent-rails.yml, agent/extensions/agent-rails.ts, templates/workflows.py, skill://git-tool, scripts/nuc-gate.py and the readme's NUC gate section.

Model routing lives in agent/config.yml; fast mode (priority tier) applies to task, kiss and sonic only. The default designer and verifier models are both Anthropic: a designer (or main agent) that edits or commits inside a Git repo requires an independent verifier family. Spawning a designer without edits does not record authorship; outside-repo scratch writes do not either.

Principles behind the proof-first flow

Distilled from poteto's pstack (findings only count when a run proves them), OpenAI Pando (a branch per agent, risk-tiered review) and trunk-based development. Each principle names where it is enforced:
  • hard blockagent-rails refuses the action
  • deterministica script decides
  • instructionagents are told, nothing stops them.
  1. 01

    Proof over opinion

    An abstract agent review is an opinion; a finding that carries the command and its output is evidence.

    • deterministicprove() runs the proofs
    • instructionverifier brief and blocking rule drop anything not run.
  2. 02

    A plan is a draft until a spike answers its open questions

    Least effort that answers a pass/fail predicate, written before anything runs, on the real surface.

    • instructionomp-dyna-workflows playbooks; kiss cuts questions first.
  3. 03

    Proofs before code

    A frozen manifest means the proof cannot be bent to fit the implementation afterwards.

    • deterministicprove() manifest and proof-file hashes
    • instructionproof task is spawned before the implementation task.
  4. 04

    Red for the right reason, green twice

    A defect proof that passes on the parent proves nothing, and one that passes once may be flaky. preserve proofs must pass at the parent; new-surface red at the parent is true by definition.

    • deterministicprove() parent overlay (expectRed substring) and two head runs.
  5. 05

    Independent, cross-family verification

    A model family shares blind spots with its own output; the verifier must not be the author's family.

    • hard blockagent-rails before_subagent_spawn (dynaflows) refuses a verifier whose family matches any author.
  6. 06

    Deterministic first, Jev second, judgement last

    Cheap, repeatable checks settle what they can; Jev warns on patterns; a model judges only the remainder.

    • deterministicprove() runs before the verifier
    • instructionJev TTSR rules warn.
  7. 07

    Structure and naming are checks, not advice

    A rule nobody runs decays; implementation needs a repo that can say no.

    • deterministicrepo pathCheck and checks.commit
    • instructionmissing either routes through setup-repository-guardrails first.
  8. 08

    The test suite is governed

    Tiers, budgets, growth limits and placement keep the suite fast enough to run on every change.

    • deterministicrepo pathCheck, checks.commit, checks.ci
    • hard blockwithout a pathCheck, agent-rails requires the tiers ref for a test path.
  9. 09

    Trunk-based units

    Short-lived agent/* branches, same-day merge, green on every commit; multi-phase work lands behind a flag with a removal criterion.

    • deterministicchecks.commit keeps commits green; agent-rails blocks hook bypasses
    • instructionskill://git-tool branch model.
  10. 10

    Risk-tiered merge authority

    Docs-only merges on green; verified work merges after one cross-family run.

    • deterministicprove() returns pass or fail; gate changes are listed, never blocking.
  11. 11

    Delegate code; the main agent never patches

    Keeps the author family known, the main context small, and fixes inside the proof loop.

    • instructionomp-dyna-workflows and task briefs; every commit runs checks.commit through the hook.
  12. 12

    Least effort, delete dead weight

    The cheapest correct change wins; cutting scope before a spike is cheaper than spiking it.

    • instructionkiss cuts criteria and open questions at Frame; clean-cutover rule.
  13. 13

    CI runs the exact SHA on owner hardware, in a sandbox

    A green status must belong to the commit being merged, and the code under test must not reach the credentials that report it.

    • deterministicNUC gate: rootless Podman + gVisor, token held by the host, status gate posted per SHA.
    • instructionskill://git-tool verify loop: submit and wait on every head; GitHub Actions is the fallback.
